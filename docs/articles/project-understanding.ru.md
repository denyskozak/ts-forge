# Как Forge разбирает React и React Native проекты

Обычного списка файлов недостаточно, чтобы объяснить поведение приложения. Forge строит структурную ментальную модель и затем подтверждает её исходным кодом.

## Что попадает в модель

- фреймворки и платформы по `package.json` и конфигурации;
- точки входа, file-based routes и экраны;
- компоненты, hooks, state, API и тестовые слои;
- React Navigation, Expo Router, Next Router и распространённые state/data библиотеки;
- внутренние связи между файлами по относительным импортам;
- признаки неполного сканирования и лимитов индекса.

Перед ответом на запросы вроде «разберись в проекте» harness автоматически читает ограниченный runtime-срез. Он начинает с entrypoint и следует по импортам к navigator, экрану, состоянию и сервисам. Это помогает маленьким локальным моделям: им не нужно сначала правильно выбрать tool, чтобы получить базовые факты.

## Инструменты агента

- `project_mental_model` возвращает обзор архитектуры и полноту индекса.
- `inspect_feature` ранжирует файлы и соседние связи для конкретной функции или пользовательского потока.
- `read_files` читает до восьми связанных файлов одним вызовом с явной отметкой усечения.
- `find_symbol`, `search_code` и `typescript_query` уточняют определения, использования и типы.

Если модель напечатала JSON read-only tool-call обычным текстом, harness распознаёт его и выполняет. Восстановление не применяется к записи файлов или запуску компилятора.

## Как читать ответ

Ментальная модель является гипотезой, построенной статическим анализом. Достоверное объяснение должно ссылаться на прочитанные файлы и отделять факты от предположений. Динамическая регистрация маршрутов, dependency injection, code generation, native-модули и runtime-конфигурация могут потребовать дополнительного поиска.

Проверить механизм на временном React Native fixture и выбранной локальной модели можно командой:

```sh
npm run eval:understanding
```

Отчёт сохраняется в `docs/project-understanding-evaluation.json`. Текущие репозиторные результаты также содержат прогон `llama3.1:8b`. На одном и том же fixture маленькая `qwen2.5:1.5b` нашла все границы потока, но придумала обновление state ответом API; `llama3.1:8b` этот отрицательный критерий прошла. Один fixture проверяет связность harness, но не измеряет качество модели на реальных больших репозиториях.
